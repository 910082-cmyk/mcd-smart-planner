# 麦麦智配 · 麦当劳消费决策看板

> 基于麦当劳官方 MCP 能力的 Web 可视化决策助手 —— 把 121 项餐品、热量、价格、优惠、门店信息，整合为「吃什么、怎么吃最划算、热量是否超标」的一站式答案。

![3D 金拱门品牌舞台](assets/m-3d-preview.png)

**在线体验（GitHub Pages，无需安装）：https://910082-cmyk.github.io/mcd-smart-planner/**

「麦麦智配」是为 **M-CODE 2026 麦当劳程序员创意开发大赛** 开发的参赛项目。它以麦当劳中国官方 MCP Server（`mcp.mcd.cn`）为唯一数据底座，提供七大决策模块，并通过程序化 3D 品牌视觉（Three.js 金拱门舞台）强化传播力。

## 它解决什么问题

消费者打开点餐界面时面对的四个具体问题，数据恰好分散在四个互不相通的 MCP 工具里：

- **吃什么**——121 项在售餐品按官方 15 大分类铺开，没有筛选手段，翻到底也不知道有什么
- **热量是否超标**——营养成分在另一个工具里，且**不含价格**，两边对不上
- **怎么吃最划算**——原价 / 现价 / 优惠券 / 立省标签分散展示，算不清「已省最多」的组合
- **哪家店、怎么去**——门店营业状态、距离、取餐方式又是一套接口

麦麦智配把四类数据整合到一个界面，让「吃什么、怎么吃最划算、热量是否超标」一次看完。

## 七大决策模块

| 模块 | 回答的问题 | 数据来源 |
|---|---|---|
| 菜单看板 | 官方 15 大分类里都有什么，支持搜索 / 分类 / 排序 | `query-meals` |
| 食物查询 | 单品的价格、热量、营养成分与商品图 | `query-meals` + `list-nutrition-foods` |
| 热量配餐 | 给定目标热量，自动生成多套不超标的搭配 | `query-meals`（仅含热量数据单品） |
| 优惠最大化 | 购物车组合的「已省最多」方案，结算条实时显示 | `query-meals` 价格字段 |
| 点单建议 | 结合人数、预算、出行方式（步行 / 骑车 / 地铁 / 自驾）推荐门店与套餐 | `query-meals` + `query-stores` |
| 积分 · 领券 | 积分折算价值、兑换进度与可领券种 | `mall-points-products` 等 |
| 功能集成 | 一览本项目实际调用的 MCP 工具、字段与实测踩坑 | 全部 |

## 技术栈

- 单页 **HTML + 原生 JavaScript**，零构建、零框架依赖，可直接双击打开或静态托管。
- **Three.js r128（本地化 `vendor/`）**：金拱门 3D 舞台（官方矢量 M 经 ExtrudeGeometry 挤出、环境反射、体积光、粒子尘埃、拖拽旋转），已内置 WebGL 降级方案（降级为官方矢量 M 标志 + 2D 大图，绝不白屏）。
- **官方品牌资产**：麦当劳官方矢量 M（`assets/mcd-logo.svg`，simple-icons CC0），品牌色经官方资料核验（`#FFC72C` / `DA291C`）。
- 数据默认**离线内联**（`data/seed-data.json` 固化为页面内 `SEED` 常量），无需联网即可演示；亦支持通过麦当劳 MCP 实时刷新。

## 快速开始

### 方式一：本地直接打开
双击 `index.html` 即可在浏览器中使用全部功能（数据已内联，无需联网）。

### 方式二：本地静态服务（推荐，避免浏览器 file:// 限制）
```bash
python -m http.server 8080
# 浏览器访问 http://localhost:8080/index.html
```

### 配置麦当劳 MCP（用于实时刷新数据，可选）
1. 在麦当劳 MCP 控制台申请 Token（<https://open.mcd.cn/mcp>，免费）。
2. 复制配置示例并按需填写：
   ```bash
   cp mcp-config.example.json mcp-config.json
   # 将 ${MCD_MCP_TOKEN} 替换为你的真实 Token（建议用环境变量注入，勿入库）
   ```
3. 在 WorkBuddy「连接器」中配置 `mcd-mcp`，即可让 AI 实时调用麦当劳 MCP 工具。

## 诚实口径

这个项目宁可少做一个功能，也不假装做一个。四条写进页面与文档的边界：

1. **演示数据是单店快照，不是实时数据。** 种子数据抓取于 2026-10-12，采样门店为麦当劳长沙五一路平和堂餐厅（`storeCode=3390081`），覆盖 121 项餐品 / 15 个分类 / 5 家长沙门店。餐品供应与价格以官方渠道实时结果为准，页脚已标注抓取时间。
2. **看板内的金额是推算值，不是官方报价。** 「优惠最大化」等模块的金额由菜单 `currentPrice` 字段推算，**未调用 `calculate-price` 官方回验**，页面内已明确标注「预估」；真实下单前必须以官方回验金额为准。
3. **热量与价格分属两套数据源。** `list-nutrition-foods` 是全国静态营养库（61 项，**按餐品名称建键，无价格、无门店维度**）；`query-meals` 有价格，但 121 项中仅 41 项（约 33%）自带热量数据。配餐模块采用交集策略——只从有热量数据的单品中生成方案，套餐类自动排除。
4. **本看板只做决策，不创建订单、不代付。** 门店推荐仅基于距离、营业状态、预约能力与取餐方式推导——麦当劳 MCP **不提供门店实时客流、排队时长数据**，页面已作能力边界声明。

## 验证链

改任何东西之后，两条检查都要跑（共 **54 项断言**）：

```bash
node tests/check_page.mjs        # 页面结构与数据自检（46 项）
python tests/test_data_pipeline.py  # 数据管道幂等性测试（8 项）
```

- `check_page.mjs`：SEED 数据自洽（121 项餐品字段齐全、商品图全部来自官方 CDN 且互不重复、分类编码无缺失、全局序与菜单一一对应、页面 SEED 与 `data/seed-data.json` 计数一致）、页面结构（唯一 main 地标、7 个 tab 与面板一一对应、品牌色、viewport 不禁缩放）、无障碍骨架（lang / 焦点可见 / reduced-motion / 无占位文本）、交互节点（全部内联脚本语法可解析、15 个事件处理器均有声明）、降级与诚实口径（图片 onerror 链、3D 异常兜底、页面明示「未调用 calculate-price」）。
- `test_data_pipeline.py`：在临时副本上真实执行 `build_menu_order.py`，验证官方 15 分类无缺失编码、全局序全覆盖 121 项，且重建产物与仓库数据**完全一致**——防止「脚本改了、数据没重建」的漂移。

## 数据来源

全部来自麦当劳 MCP 服务的真实返回，**没有任何人工编造的数字**：

| 数据 | MCP 工具 |
|---|---|
| 在售餐品（名称 / 现价 / 原价 / 分类 / 商品图） | `query-meals` |
| 营养成分（热量 / 蛋白 / 脂肪 / 碳水 / 钠 / 钙） | `list-nutrition-foods` |
| 附近门店（地址 / 距离 / 营业状态 / 可预订） | `query-stores` |
| 组合实付金额与优惠叠加 | `calculate-price`（当前仅文档口径，未在演示中调用） |
| 积分兑换商品 | `mall-points-products` 等 |
