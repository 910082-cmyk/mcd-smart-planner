# MCP 集成说明（MCP_INTEGRATION.md）

## 概述

「麦麦智配」以麦当劳中国官方 MCP Server 为唯一数据底座，所有菜单、价格、营养、门店信息均来源于麦当劳 MCP 工具的真实返回。看板默认将实测数据固化为离线种子（`data/seed-data.json` → 页面内联 `SEED`），以保证零联网即可演示；同时保留通过 WorkBuddy 实时调用 MCP 刷新数据的能力。

## MCP Server

| 项 | 值 |
| --- | --- |
| 名称 | 麦当劳官方 MCP（`mcd-mcp`） |
| 协议 | Streamable HTTP |
| 地址 | `https://mcp.mcd.cn` |
| 鉴权 | Bearer Token（通过麦当劳 MCP 控制台申请） |
| 配置示例 | `mcp-config.example.json` |

## 实际使用的 Tool

### 1. `query-meals` —— 菜单查询
- **能力**：获取指定门店在售餐品，返回名称、分类、价格、商品图、促销标签。
- **本项目用法**：
  - 抓取门店 `3390081`（长沙五一路平和堂）全量菜单，固化为 `seed-data.json` 的 `menu` 字段（**121 项**）。
  - 读取 `categories` 顺序，固化麦当劳官方 15 大分类（见 `scripts/build_menu_order.py`）。
  - 为「菜单看板」「食物查询」「热量配餐候选池」提供数据。
- **关键字段**：`name` / `currentPrice` / `originalPrice` / `cat` / `tags` / `kcal` / `image`。

### 2. `calculate-price` —— 价格计算
- **能力**：计算组合餐品的最终实付价格（含优惠叠加）。
- **本项目用法**：为「优惠最大化」「购物车合计」「点单建议」计算实付金额与「已省」金额。
- **注意**：返回金额单位为**分**，前端展示须除以 100。

### 3. `list-nutrition-foods` —— 营养查询
- **能力**：查询餐品营养成分（热量等），全国静态营养库。
- **本项目用法**：为「热量配餐」提供热量数据。
- **注意**：该数据源**不含价格**；与 `query-meals` 的价格分属两套数据。配餐模块采用**交集策略**——仅对有热量数据的单品参与配餐，套餐类自动排除（121 项中约 33% 含热量数据）。

### 4. `query-stores` —— 门店查询
- **能力**：查询附近门店、地址、距离、营业状态与可预订性。
- **本项目用法**：为「点单建议 / 出行方式」提供门店选择（已抓取长沙 5 家门店的营业时间与距离）。

## 数据流转

```
麦当劳 MCP 工具
   │  （WorkBuddy 调用 / 脚本抓取，见 scripts/）
   ▼
data/seed-data.json          ← 实测种子（storeCode / menu / stores / nutrition）
   │  内联为页面常量 SEED
   ▼
index.html 看板              ← 离线渲染，零 CORS / 零联网依赖
```

看板默认离线运行：商品图来自麦当劳官方 CDN（`menu-img.mcd.cn`），该 CDN **不返回 CORS 头**，直接做 WebGL 纹理会污染 canvas；因此视觉采用程序化 3D 建模与官方矢量资产，彻底规避该限制，可稳定部署于 GitHub Pages。

## 业务价值

四个 MCP 工具分别掌握菜单、价格、营养、门店四类孤立信息。本项目把它们整合为一个面向「消费决策」的统一界面：

- 吃什么 —— 菜单看板 + 食物查询
- 怎么搭配热量不超标 —— 热量配餐
- 用哪张券最划算 —— 优惠最大化
- 哪家店现在营业、怎么去 —— 门店查询 + 出行建议

相较单纯罗列菜单，显著降低了消费者的决策成本，也直观展示了麦当劳 MCP 能力的组合价值。

## 合规说明

- 配置文件仅使用环境变量占位符（`${MCD_MCP_TOKEN}`），不含真实 Token / 密钥 / 凭证。
- 商品图来自麦当劳官方 CDN，仅用于展示；离线版已规避 CORS 纹理污染问题。
- 数据均为参赛演示用途，实际消费以麦当劳官方渠道实时结果为准。
